## Stack

Java 21, Spring Boot 3.5, Maven (wrapper included), PostgreSQL 17 in Docker, Liquibase XML migrations,
Spring Modulith for module boundaries, JUnit 5 with H2 for tests.

## Run the app

Requires Java 21 and Docker.

```bash
cp .env.example .env          # then set DB_USERNAME, DB_PASSWORD and JWT_SECRET
docker compose up -d          # starts PostgreSQL on localhost:5432
./mvnw spring-boot:run        # applies Liquibase migrations, starts on :8080
```

Health check: `curl localhost:8080/actuator/health`.

| Variable | Purpose |
|---|---|
| `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USERNAME`, `DB_PASSWORD` | PostgreSQL connection |
| `JWT_SECRET` | HMAC-SHA256 signing key, at least 32 bytes: `openssl rand -base64 48` |
| `SHORT_URL_BASE` | Prefix for returned short URLs (default `http://localhost:8080/r/`) |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | Optional: creates an ADMIN account on startup if not registered yet |

No secret has a default in source; the app fails to start without `JWT_SECRET`.

### Calling the API

Everything except register/login, redirects, health and product reads needs a bearer token:

```bash
curl -X POST localhost:8080/api/v1/auth/register -H 'Content-Type: application/json' \
  -d '{"email":"user@example.com","password":"password123"}'
TOKEN=$(curl -s -X POST localhost:8080/api/v1/auth/login -H 'Content-Type: application/json' \
  -d '{"email":"user@example.com","password":"password123"}' | jq -r '.data.accessToken')
curl localhost:8080/api/v1/tasks -H "Authorization: Bearer $TOKEN"
```

Tokens expire after 15 minutes. Admin-only routes need the `ADMIN_EMAIL` account.

## Features

| # | Endpoints | Key decision |
|---|---|---|
| 1 | `POST/GET /api/v1/tasks` (`?status=TODO\|IN_PROGRESS\|DONE`), `GET/PUT/DELETE /api/v1/tasks/{id}` | Bean Validation returns one message per invalid field through the shared `GlobalExceptionHandler`; `@Version` guards concurrent updates. |
| 2 | `POST /api/v1/urls`, `GET /api/v1/urls/{code}/stats`, `GET /r/{code}` | The same URL and expiry returns the existing code (unique dedupe key). Visits use an atomic `UPDATE ... SET visit_count = visit_count + 1`, so no count is lost under parallel opens. |
| 3 | `POST /api/v1/auth/register`, `POST /api/v1/auth/login`, `GET /api/v1/users/me`, `GET /api/v1/admin/users` (ADMIN) | Stateless JWT signed with `JWT_SECRET`, BCrypt passwords; 401 and 403 are JSON in the shared envelope. |
| 4 | `GET /api/v1/products`, `GET /api/v1/products/{id}`; `POST/PUT/DELETE` (ADMIN) | Filters `category`, `minPrice`, `maxPrice`, `inStock`, `q` combine through JPA Specifications; `page`, `size` (max 100), `sort=field,dir`. Lookups by id are cached in Caffeine and evicted on update or delete; see `GET /actuator/caches` and `/actuator/metrics/cache.gets` (ADMIN). |
| 5 | `POST /api/v1/orders` with `Idempotency-Key` header, `GET /api/v1/orders/{id}`, `POST /api/v1/orders/{id}/cancel` | Each item reserves stock with a conditional `UPDATE ... WHERE stock >= :qty` in one transaction, so any shortfall rolls back the whole order (409). A repeated `Idempotency-Key` for the same customer returns the original order. |

Prices are stored in cents (`priceCents`). 100 products are seeded by Liquibase from
`db/changelog/releases/1.4.0/products.csv`, generated by `scripts/generate_products_csv.py`.

## Run the tests

```bash
./mvnw verify
```

Tests run against an in-memory H2 database in PostgreSQL mode with the same Liquibase changelogs, so
no Docker is needed. Notable tests: `TaskApiIntegrationTest` (400 field errors, 404),
`ShortUrlIntegrationTest` (concurrent visit counts), `AccessControlIntegrationTest` (USER gets 403 on
the admin endpoint), `ProductCachingTest` (repeated lookups skip the database, updates are not stale),
`OrderPlacementTest` (50 simultaneous orders against stock 10: exactly 10 succeed, stock ends at 0)
and `OrderIdempotencyTest` (a retry creates one order). `verify` also runs Spotless; fix formatting with `./mvnw spotless:apply`.

```
  db.changelog-master.xml          includes each release in order
  releases/<version>/              one directory per release, changeset ids prefixed with the version
```

## Database versioning

Every schema change is a Liquibase XML changeset. Each feature ships as a minor release (`1.1.0` for
Q1 through `1.5.0` for Q5): the `pom.xml` version, the `releases/<version>/` directory and a closing
`tagDatabase` changeset all carry the same number, so a rollback can target any release tag.
Applied changesets are never edited; a fix is a new changeset.

## Error format

Every response, success or error, uses one JSON envelope:

```json
{ "success": false, "message": "Request validation failed", "errorCode": "VALIDATION_FAILED",
  "errors": [{ "field": "title", "message": "must not be blank" }], "timestamp": "..." }
```
